# P2P Capital Lab — USDT/KZT

Исследовательская система для одного вопроса: **является ли наблюдаемый спред
на P2P-рынке USDT/KZT рыночной неэффективностью или премией за
непрайсимый риск контрагента.**

Поверх измерения построен второй слой: что происходит с капиталом, если
симулированную прибыль систематически отчислять в долгосрочный портфель.

> **Read-only.** Пакета `execution/` в проекте нет и не должно появиться.
> Система физически неспособна отправить ордер — соответствующего кода
> не существует. Все результаты помечены как симуляция, ни одной реальной
> операции не совершалось.

## Главный результат на сегодня

Первоначальная гипотеза — «чем выше качество контрагента, тем ниже спред» —
**не подтверждается.** Заявленное убывание оказалось артефактом метрики.

```
страты качества ВЛОЖЕНЫ:  premium ⊂ good ⊂ basic ⊂ any
метрикой был МАКСИМУМ спреда внутри страты

max по надмножеству не может быть меньше max по подмножеству
⇒ убывание получалось при ЛЮБЫХ данных
```

Проверка на живых наблюдениях: на вложенных стратах порядок не нарушился
ни разу из 32 моментов, на взаимоисключающих полосах — в 85%.

После пересчёта по устойчивым квантилям эффект **уменьшился вдвое**:
+3.16% вместо +6.18%, и он несимметричен — сторона продажи не двигается,
весь прирост даёт верх стороны покупки в плотной книге.

Уцелело одно утверждение: **среди наиболее репутабельных контрагентов
исполнимого положительного спреда не наблюдается.**

## Пять найденных дефектов собственной модели

Каждый был найден проверкой числа, которое выглядело слишком хорошо.
Все пять завышали картину.

| Дефект | Как проявлялся | Цена |
|---|---|---|
| Тавтология вложенных страт | убывание спреда по качеству | весь главный результат |
| Потеря дробных требований | `int("96.5")` → падение анализа и тихий ноль | смещение в логике исполнимости |
| Ликвидность суммой, а не уровнем | «227 005 млн ₸» на рынке в сотни миллионов | нечитаемая метрика |
| Слепая продажа в переставленное объявление | продажа по 467 при 128 альтернативах по 486 | 11 935 ₸ на одной сделке |
| Метрика росла с размером книги | корреляция +0.757 при неподвижной медиане | половина «возможности» |

Шестым идёт троттлинг биржи: интервал в 20 секунд оказался физически
недостижим, доля неполных обходов дошла до 32.3% за сутки. После подъёма
интервала до 120 секунд — 0%.

## Как устроено

```
книга заявок Bybit
      ↓  collector/      опрос публичного эндпоинта, устойчивый к троттлингу
      ↓  storage/        SQLite: события, а не снимки
      ↓  analysis/       матчинг пар, сегменты, экономика, симуляция
      ↓  capital/        распределение прибыли, бумажные портфели
      ↓  dashboard/      локальная панель, только 127.0.0.1
```

**Хранятся факты, выводы считаются на лету.** Возможности не сохраняются
намеренно: возможность есть функция от состояния книги и конфигурации
порогов, и запись её в базу заставила бы пересчитывать всю историю при
каждом изменении правила.

**Журнал обходов — часть данных, а не служебная таблица.** Без него
невозможно отличить «заявка ушла с рынка» от «сборщик не работал».
Интервал присутствия закрывается только после полного успешного обхода.

## Что система отказывается считать

Вероятность того, что перевод дойдёт, и вероятность блокировки счёта
**не наблюдаемы в API ни в каком виде** — а знак результата определяют
именно они. Раньше они молча подставлялись единицей и нулём, и симуляция
выдавала 4.7% в сутки: не найденную неэффективность, а цену допущения,
что риска нет.

Теперь результат показывается сеткой по обоим неизвестным:

```
возврат    90%      95%      98%      99%    99.5%     100%
   0%   -34.36   -14.87    -3.17     0.73     2.68     4.63
  50%   -15.10    -5.24     0.68     2.65     3.64     4.63
  85%    -1.61     1.51     3.38     4.00     4.32     4.63
```

Прежний «результат» — правый верхний угол, единственная ячейка без риска.
Безубыточность требует успешности 98.8% при полной потере тела и 92.6%
при возврате 85%.

Стоимость инвестиционного портфеля не считается: **источника котировок
акций и облигаций у проекта нет.** Показывается «нет данных», а не ноль.

## Ограничения

- Наблюдения не независимы: одна заявка порождает сотни состояний.
  Нужна кластеризация по диадам, не сделана.
- Доверительные интервалы не считаются. Во всех полосах меньше 30
  независимых кластеров.
- Разбивка по часу суток не реализована, хотя данные намекают: ночью при
  74 заявках разрыв +0.21%, днём при 450 — около 6%.
- Августовский разведочный прогон утрачен вместе с сырыми данными; его
  цифры сохранены как источник гипотезы и не используются как результат.
