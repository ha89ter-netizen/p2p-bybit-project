# P2P Research — USDT/KZT

Исследовательский сбор данных по P2P-рынку USDT/KZT. **Read-only.**
Пакета `execution/` в проекте нет и не должно появиться: система физически
неспособна отправить ордер, потому что кода для этого не существует.

## Что это отвечает

Один вопрос: **является ли наблюдаемый спред рыночной неэффективностью
или премией за непрайсимый риск.** Дискриминатор — не величина спреда,
а его поведение во времени и по стратам качества контрагента.

Прогноз PnL сознательно не считается до ответа на этот вопрос.

## Запуск

```bash
cd ~/Documents/p2p_research
./run.sh                              # коллектор, Ctrl+C для остановки
python3 -m scripts.report_block_a     # отчёт по накопленному
python3 -m scripts.send_digest --dry-run   # дайджест в терминал
python3 -m unittest discover -s tests -t .
```

## Telegram

Дайджест раз в N часов: таблица пар по бакетам спреда. Только отправка —
ни команд, ни обработчиков, ни webhook. Принимать что-либо от
пользователя система не умеет по построению, поэтому класс ошибок
«команда случайно инициировала сделку» исключён физически.

```bash
export TELEGRAM_BOT_TOKEN="123456:AA..."   # от @BotFather
export TELEGRAM_CHAT_ID="123456789"        # ваш id от @userinfobot
./run.sh
```

Проверить без отправки: `python3 -m scripts.send_digest --dry-run`.
Отправить один раз: `python3 -m scripts.send_digest`.

Необязательные переменные:

| переменная | по умолчанию | что делает |
|---|---|---|
| `TELEGRAM_DIGEST_AT` | `8,20` | часы отправки по местному времени |
| `TELEGRAM_DIGEST_HOURS` | `12` | окно, за которое считается таблица |
| `TELEGRAM_AMOUNT_KZT` | `300000` | сумма, на которой считаются пары |
| `TELEGRAM_ROWS` | `5` | строк в каждом бакете |
| `TELEGRAM_MIN_ORDERS` | `200` | сделок контрагента за 30 дней |
| `TELEGRAM_MIN_RATE` | `97` | completion rate контрагента |
| `TELEGRAM_MIN_AD_FINISH` | `50` | сделок через само объявление |
| `TELEGRAM_TZ` | `Asia/Almaty` | часовой пояс в заголовке |

Токен и chat_id читаются только из окружения, в репозиторий не попадают
и не появляются в тексте ошибок.

Три порога качества — не украшение. Без них в бакет «3%+» попадают
контрагенты с четырьмя сделками за месяц и объявлением, через которое
прошла одна сделка. Показывать такое как возможность значит вводить
себя в заблуждение. Отсеянные считаются отдельной строкой, чтобы ничего
не пряталось.

Пара схлопывается по ключу (buy_ad, sell_ad) за всё окно: связка,
простоявшая три часа, это ОДНА возможность, а не 540. Иначе статичная
витрина выглядела бы как бурная торговля.

Зависимостей нет — только стандартная библиотека Python 3.11+.
`run.sh` оборачивает запуск в `caffeinate -i`, чтобы машина не уснула
в простое. Закрытая крышка это не отменяет: пропуск честно попадёт
в `poll_run` и будет виден в разделе «покрытие данных».

## Источник данных

```
POST https://api2.bybit.com/fiat/otc/item/online
POST https://api2.bybit.kz/fiat/otc/item/online
```

**Эндпоинт не документирован.** Авторизация не требуется (проверено
28.08.2026). Официальный `/v5/p2p/*` требует статуса General Advertiser
и розничному пользователю недоступен. Вся работа с биржей изолирована
в `collector/bybit_public.py`; сырые ответы сэмплируются в `raw_response`,
чтобы при смене формата можно было переразобрать историю.

## Четыре факта об API, выясненные на живых данных

0. **`quantity` — исходный объём объявления, а НЕ доступный остаток.**
   Доступно `lastQuantity` = `quantity − executedQuantity − frozenQuantity`.
   В живой книге 10 из 12 объявлений имеют `quantity != lastQuantity`;
   крайний наблюдённый случай — `quantity=131203.74` при `last=2480.08`,
   то есть счёт ликвидности по `quantity` завышает её в 53 раза.
1. **`finishNum` и `orderNum` — счётчики ОБЪЯВЛЕНИЯ, не контрагента.**
   Один мерчант держит два объявления на одной стороне со 100 и 24
   сделками при общем `recentOrderNum=1107`. Репутация человека —
   это `recentOrderNum` / `recentExecuteRate`; `finishNum` — зрелость
   объявления. Смешивать их значит мерить не то.
2. **`latestPayTime` / `latestReleaseTime`** дают фактическое время
   исполнения конкретного контрагента: медиана 41–80 с, p90 216–287 с.
3. **`tradingPreferenceSet`** содержит требования объявления К НАМ
   (KYC, мин. сделок за 30 дней, completion rate, гражданство).
   Прочитать можем — соответствуем ли, API не сообщает. Поэтому это
   флаг риска, а не фильтр исполнимости.

## Модель хранения

Наивная запись всей книги каждые 20 с даёт ~1.7 млн строк в сутки, 99%
из которых дубли. Здесь:

* `ad_state` — строка только когда состояние реально изменилось
  (~8 изменений за цикл вместо 400);
* `ad_presence` — интервалы жизни, а не тики;
* `poll_run` — каждый обход, включая неудачные.

`poll_run` — не служебная таблица, а часть данных: без неё нельзя
отличить «объявление исчезло» от «коллектор спал». Интервалы присутствия
закрываются **только после полного успешного обхода** — один таймаут
не должен объявлять половину книги мёртвой.

`opportunities` не хранится намеренно: возможность — это функция от
(состояние книги, конфиг). Сохранив её, пришлось бы пересчитывать всю
историю при каждой смене порога.

## Производительность анализа

Наивный перебор пар — 90 buy x 310 sell = 28 000 комбинаций на каждую
(сумму, страту), 12 таких комбинаций на момент, ~4300 моментов за 72 часа
сбора. Отчёт бы не досчитался. `iter_pairs_by_spread()` лениво сливает
кучей отсортированные потоки и отдаёт пары по убыванию спреда, поэтому
`best_pair()` останавливается на первой: **2.2 мс на момент**, то есть
72 часа данных обсчитываются за ~9 секунд. Эквивалентность наивному
перебору закреплена тестом на 40 случайных книгах.

## Чего этот проект не может

`P(перевод дойдёт)` и `P(счёт заблокируют)` не наблюдаемы в API ни в
каком виде, а именно они определяют знак результата. `recentExecuteRate`
— статистика контрагента со всеми, а не оценка нашей вероятности;
использовать её как `P_release` — методологическая ошибка.

Поэтому `analysis/economics.py` возвращает не прогноз прибыли, а
`breakeven_p_completion()` — «при какой вероятности успеха это
перестаёт быть убыточным». Утверждение в такой форме проверяется
реальными сделками. Прогноз PnL — нет.

## Результаты прогона

`data/FINDINGS.md` — самодостаточный отчёт: цифры плюс инструкция, как
их читать, и список уже известных ловушек интерпретации. Пишется
автоматически вместе с каждым дайджестом, так что остаётся свежим, даже
если сессия оборвалась.

```bash
python3 -m scripts.export_findings   # обновить вручную
```

Файл рассчитан на чтение без всякого контекста — в том числе агентом в
новой сессии.
